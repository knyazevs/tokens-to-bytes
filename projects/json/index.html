Что здесь происходит

Интерфейс ничего не знает о JSON: он копирует UTF-8 байты в память модуля по адресу json_input_ptr(), вызывает json_parse(len) и читает счётчики. Разбор, декодирование строк и \u-последовательностей, включая суррогатные пары, живут внутри wasm. Модуль ничего не импортирует.

API

  • json_input_ptr() → i32 — входной буфер (64 КиБ);
  • json_parse(len) → i32 — 0 при успехе, иначе код ошибки;
  • json_error_pos(), json_error_code() — позиция и код;
  • json_root_type() — 0 null, 1 false, 2 true, 3 number, 4 string, 5 array, 6 object;
  • json_root_number(), json_root_len(), json_root_ptr() — корневое значение;
  • json_nodes(), json_depth(), json_numbers(), json_strings(), json_string_bytes() — структура.

Коды ошибок

1 неожиданный символ, 2 неожиданный конец, 3 данные после значения, 4 глубина больше 64, 5 некорректное число, 6 некорректная строка или escape, 8 превышен буфер.

Реализации

  • json.wasm — ручной байткод (json.wat, собран через wasm-as);
  • json-rust.wasm, json-assemblyscript.wasm, json-c.wasm, json-cpp.wasm — Rust / AssemblyScript / C / C++; json-cpp-opt.wasm — тот же C++ с -O3.

Запуск

Ручная сборка встроена в страницу как base64, поэтому при открытии двойным щелчком работает и file://. Остальные движки загружаются через fetch: для них нужен локальный сервер, например python -m http.server.
